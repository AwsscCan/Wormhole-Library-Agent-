## P02：图书馆与来源联邦

### 已验证可保留内容

- OpenAlex、Open Library 与本地 seed 均有适配器，具备超时、网络、429 和解析错误分类。
- DOI、ISBN、标题/作者/年份的去重与多来源证据合并有较完整单测。
- `GET/POST /api/library/topic` 具备请求校验和统一错误结构，未破坏旧 Living Library consent 回归。

### E-001：P05 要求的 P02 稳定目录端口

- source_ref: `lib/research/catalogPort.ts:3-20`; `lib/research/types.ts:4-16`
- repro_command: `git show 23cee51:lib/research/catalogPort.ts; git show 23cee51:lib/research/types.ts`
- evidence: P05 消费 `SourceTransparentCatalogPort.searchTopic({query, limit})`，需要 `TopicLibraryResult.resources`、每条 `ResourceCard` 的 provenance，以及 `live | partial | unavailable` 的来源状态。

### E-002：P02 导出的是平行 API，而不是可绑定端口

- source_ref: `df80d1a:lib/federation/topicLibrary.ts:47-82`; `df80d1a:lib/federation/types.ts:35-62`
- repro_command: `git grep -n "SourceTransparentCatalogPort\|bindPackage02SourceCatalogPort\|TopicLibraryResult" df80d1a`
- evidence: P02 只提供 `getTopicLibrary({topic, limit})`，返回 `EvidenceItem[]`、`failures` 和 `sources`；不存在 `searchTopic` adapter 或绑定函数。

### E-003：成功但空的来源不会出现在状态中

- source_ref: `df80d1a:lib/federation/federation.ts:92-131`; `df80d1a:lib/federation/topicLibrary.ts:62-73`
- repro_command: `git show df80d1a:lib/federation/federation.ts; git show df80d1a:lib/federation/topicLibrary.ts`
- evidence: `sources` 仅由返回条目和失败推导。一个远端源成功返回空数组时既不产生 `empty` failure，也不保留 attempted 状态。

### F-001：P02 不能为 P05 提供真实来源透明馆藏

- severity: blocker
- evidence_ids: [E-001, E-002]
- impact: P05 只能进入“catalog port is not integrated”的显式 unavailable 分支；真实联邦结果无法进入推荐、星图或馆藏深链。
- remediation: 由 P02 实现 `SourceTransparentCatalogPort` adapter，将 `EvidenceItem` 明确投影为含 `ResourceCard` 必填字段的 `SourceTransparentResource`；确定多来源记录的主 provenance 与附加来源表达，并在 P01 composition 中绑定该端口。

### F-002：来源透明度与可用性状态不成立

- severity: high
- evidence_ids: [E-003]
- impact: UI 无法区分远端未查询、查询失败、查询为空和被禁用；更不能可靠映射为 P05 所需 `live`、`partial`、`unavailable`。
- remediation: 对每个 enabled source 显式记录 `success`、`empty`、`failed`、`disabled`；补充 all-empty、部分失败但 seed 命中、全部不可用的端口与 API contract 测试。

### P-001：P02 到 P05 的阻断路径

1. P05 请求 `SourceTransparentCatalogPort.searchTopic()`。— evidence: E-001 — finding: F-001
2. P02 仅暴露独立 `getTopicLibrary()` / HTTP route，未实现或绑定该端口。— evidence: E-002 — finding: F-001
3. P05 无法消费真实联邦资源，转入 explicit unavailable。— evidence: E-001 — finding: F-001

## P04：可审计私有记忆 RAG

### 提交范围说明

`0eafd6c` 是“merge origin/main into codex/v3.3-p04-memory-rag”。相对第一父提交的 diff 只包含 P02 来源联邦文件；P04 的账本、索引、推断和端口代码没有改变。因此本报告按提交中实际继承的 P04 实现 `7c8a586` / `0fa20f2` 验收，不把合并带入的 P02 文件视为 P04 修复。

### 已验证可保留内容

- owner/session 过滤、删除后索引移除、单次 `too_hard` 不直接升格长期偏好、资料不足拒答的方向正确。
- 四组实验脚本可运行，能作为修复后的回归框架。

### E-004：账本暴露可变内部引用

- source_ref: `lib/research/memory/ledger.ts:20-53`
- repro_command: `appendLearningEvent(...)` 后修改返回对象，再调用 `findLearningEvent()` / `listLearningEvents()`
- evidence: append 直接返回已写入数组的 event；list/find 也直接返回状态内对象。运行时复现：修改返回 event 的 `kind` / `query` 会改写已保存账本内容。

### E-005：所谓 semantic 分数只基于共享 token

- source_ref: `lib/research/memory/indexStore.ts:105-143`
- repro_command: 为 “automobile maintenance” 添加片段，查询 “car servicing”
- evidence: 实现为 token TF cosine；没有共享 token 时 lexical 和“semantic”均为 0，查询返回空。

### E-006：P04 没有生产身份、持久化和 P05 DTO 边界

- source_ref: `lib/research/memory/ledger.ts:12`; `lib/research/memory/indexStore.ts:25`; `lib/research/memory/types.ts:44-61`; `lib/workbench/ports.ts:11-25`
- repro_command: 新进程读取账本；将 P04 `defaultMemoryReadPort` 赋给 P05 binding；搜索 P04 对 P01/P02/P03 端口的 import
- evidence: 账本、索引、推断与绑定均在 `globalThis`；写入口信任外部 `ownerId`；P04 preference 只有 `conceptId`，P05 需要 `key/value`；P04 不消费 P02 provenance 或 P03 session。

### F-003：append-only 账本不具备不可篡改性

- severity: blocker
- evidence_ids: [E-004]
- impact: 调用者能改写历史事件，偏好证据链不可审计，违反 P04 的核心承诺。
- remediation: 在所有读写边界返回深拷贝/readonly DTO，持久层采用 append-only 记录并校验唯一 ID；为 append/list/find 的引用隔离增加回归测试。

### F-004：混合检索没有实际语义能力

- severity: blocker
- evidence_ids: [E-005]
- impact: 无词面交集的同义查询不能召回；现有实验以存在重叠词元的样例代替语义验证，不能满足责任书的同义研究问题召回要求。
- remediation: 使用真实向量嵌入或经验证的本地语义表示；以中英文无 token-overlap 的同义 fixture 执行 lexical-only 与 hybrid 消融，并提交可复现原始结果。

### F-005：P04 不能作为可部署的 P05 私有记忆提供方

- severity: blocker
- evidence_ids: [E-006]
- impact: 状态会随重启丢失，外部调用者可冒充任意 owner，且 P05 无法直接使用 preference DTO；也缺 P02/P03 的可追溯来源与会话关联。
- remediation: 使用 P01 server principal 推导 owner；以 Prisma/SQLite、迁移和重启测试持久化账本/索引/撤销状态；接入 P02 provenance 与 P03 session 只读端口；提供 P05 兼容 adapter，例如把概念偏好映射为 `key: "conceptId"`、`value: conceptId`。

### P-002：P04 到 P05 的阻断路径

1. P01 应从 server principal 派生 owner 后写入 P04。— evidence: E-006 — finding: F-005
2. P04 应持久化不可变事件并返回兼容 `MemoryReadPort`。— evidence: E-004, E-006 — finding: F-003, F-005
3. P05 读取 snippets 与 `key/value` preferences。— evidence: E-006 — finding: F-005
