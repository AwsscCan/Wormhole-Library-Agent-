# Wormhole Library Agent 演示视频稿

## 视频定位

**建议时长：** 12–15 分钟  
**演示目标：** 证明这是一个能够从模糊研究目标出发，检索真实来源、组织知识、沉淀记忆并完成证据约束写作的可运行 Web 应用，而不是静态页面。  
**画面风格：** 默认使用“深夜纸墨”主题；录制时保持浏览器地址栏可见若需证明真实页面，但不要展示 API 密钥、Cookie、个人馆藏凭据或私人文件内容。

## 0. 开场与产品定位（0:00–0:40）

**画面：** 打开 `http://localhost:3000` 首页。

**旁白：**

“这是 Wormhole Library Agent，一个面向个人研究的知识管理工作区。它把搜索、真实馆藏、个人知识星图、混合记忆、笔记和证据约束写作放在同一条可恢复流程里。今天我会从一个模糊课题开始，展示它如何自动扩展检索、合并来源、生成全量总结，并继续进入星图和写作。”

## 1. 从模糊目标开始 AI 全量搜索（0:40–2:30）

**操作：** 在首页输入“如何用混合记忆提升研究型 AI Agent 的检索与写作质量”，选择“AI 全量搜索”，保留准确搜索，点击开始。

**旁白：**

“用户不需要一开始就想好完整关键词。AI 全量搜索会把目标拆成多个检索意图，例如混合记忆、研究型 Agent、检索增强和写作质量，再交给联邦馆藏执行。准确搜索是默认路径；意外度滑块用于主动发散，不会让默认搜索失去准确性。”

**画面要展示：** 加载状态、目标拆解、多个实际查询、候选列表和来源标签。滚动确认结果不是只有一个内置来源，并点击至少一个来源链接。

**旁白：**

“这里展示的是实际执行过的查询和来源，而不是预先写死的几篇卡片。每条结果都保留来源标签和可打开的原始链接。OpenAlex、Open Library 以及可用的其他馆藏源会按来源状态参与合并；某个远程源为空或暂时不可用时，会明确显示状态。”

## 2. 展示全量总结与相关性结果（2:30–3:40）

**画面：** 聚焦结果区的“AI 搜索总结 · 全部候选”。

**旁白：**

“右侧说明 AI 实际走过的检索路径，下面给出已扫描候选总数和按相关性初选的数量。这里的总结基于全部候选的书目元数据和可用摘要线索，并明确提醒正式引用需要逐条打开来源核验。它解决的是搜索引擎式的全局速览，不等同于对单篇文献生成详细综述。”

**操作：** 点击“查看星图”和“已存笔记”入口，回到研究会话后继续。

## 3. Open Library 馆藏星图下钻（3:40–5:00）

**画面：** 首页右侧切换到“馆藏分类”。

**旁白：**

“馆藏分类不是装饰。中心父星连接真实的 Open Library 分类；点击一个分类后，接口会读取它的子分类和书目，子星继续与父星连线。”

**操作：** 点击“计算机科学”或现场可见的分类；再点击“Artificial intelligence”等子分类；点击一个书目节点，确认打开 Open Library 原始地址；点击左上角返回上一级；再在分类搜索框输入一个分类名称并打开。

**旁白：**

“这个过程可以递归进行，也可以用分类搜索直接进入。书目节点可以打开原始页面，所以用户不会被困在只有一个词条的前端演示里。”

## 4. 研究工作区与两种星图（5:00–6:50）

**画面：** 进入当前研究会话的研究工作区地图。

**旁白：**

“研究工作区沿用同一套 Knowledge Atlas 视觉语言，但这里同时提供两种入口。我的星图显示当前会话、搜索结果、知识关系和个人覆盖层；馆藏总图复用实时 Open Library 星图，方便从学科分类下钻到真实书目。”

**操作：** 展示“我的星图”，打开“记忆图层”，拖动“知识距离”；再点击“馆藏总图”，完成一次分类下钻和返回。

**旁白：**

“个人星图里的距离滑块改变知识坐标间的间距。记忆图层以不同色彩和亮度显示长期偏好、近期事件和 RAG 命中；搜索频次越高，相关节点会越亮。馆藏总图则使用真实父子连线和递归分类，不再是模拟的蓝图。”

## 5. 研究记录和来源沉淀（6:50–7:40）

**操作：** 回到研究工作台，打开搜索结果或工作台列表，展示记录；删除一条测试记录并确认列表更新。

**旁白：**

“研究会话是持久化记录，可以刷新、重启服务后恢复，也可以从界面删除。删除会连同该会话的工作台状态、证据篮和写作工件一起清理，避免留下无法打开的旧深链。”

## 6. 上传资料与知识库选择（7:40–8:40）

**画面：** 进入写作工作台，展示“材料与证据”区域。

**操作：** 拖入一份演示用 Markdown 或文本文件；展示上传后的保留选项，选择“仅当前工作流，默认 30 天”或“进入知识库”，确认文件出现在材料列表中。

**旁白：**

“写作台提供真实上传入口。资料可以只服务于当前工作流，默认保留三十天，也可以明确选择进入个人知识库。这个选择会影响资料的生命周期和后续 RAG 范围，不会在用户不知情时自动把临时文件长期保存。”

## 7. 证据约束写作工作流（8:40–10:40）

**操作：** 点击“发现候选”，展示候选来源、作者和核验状态；逐条确认至少三条；填写任务焦点；选择语言、引用格式和模型预设；启用检查点并运行。

**旁白：**

“文献综述和全量总结已经在探索台完成；写作台的职责是把选定证据转成可审阅文本。系统先发现候选，再要求人工逐条确认。未确认的候选不会进入生成上下文。”

**画面：** 展示运行日志、检查点暂停、草稿编辑器和实时预览。

**旁白：**

“生成过程按材料、证据、提纲、初稿和复核阶段推进。开启检查点后，初稿会暂停等待人工决定。左侧可以修改 Markdown，右侧实时预览；模型不可用时会使用带证据标记的本地可追溯草稿，并明确标注，而不是伪装成模型结果。”

**操作：** 保存编辑，建立证据回链，确认人工复核，导出 Markdown。

**旁白：**

“完成证据回链和人工复核后才能导出。导出的文本保留引用标记，用户可以沿着来源回链进行最终核验。”

## 8. 笔记、混合记忆与恢复（10:40–11:40）

**画面：** 进入 `/notes`，新建一条 Markdown 笔记；再进入 `/memory`。

**旁白：**

“笔记是个人知识库的一部分，保存后会在刷新和重启后继续存在。记忆页显示当前主体隔离的偏好、事件和召回结果。搜索、上传、阅读和反馈会成为后续研究的上下文。”

**操作：** 回到星图打开记忆图层，展示命中原因和亮度变化；可选地刷新页面证明状态恢复。

**旁白：**

“有 Ollama 嵌入模型时，系统使用真实向量召回；没有时会明确写出词法降级。这里的透明状态很重要：产品不会把简单字符匹配说成语义理解。”

## 9. Provider、DeepSeek、CC Switch 与个人馆藏源（11:40–12:50）

**画面：** 进入 `/settings/providers`。

**操作：** 展示 Provider 表单、DeepSeek 快速配置、模型预设、CC Switch 显式导入入口；输入演示值但不要保存真实密钥；展示馆藏源配置和主题/语言入口。

**旁白：**

“普通用户不需要修改代码就可以配置自己的模型和馆藏源。DeepSeek 使用 OpenAI 兼容接口配置，CC Switch 只导入脱敏的模型元数据，不隐式复制凭据。高校馆藏如果需要校园网、SSO、IP 白名单或订阅权限，应用会要求相应授权，不绕过机构边界。”

**操作：** 切换语言或主题后进入另一页面，证明选择跨页面生效；切回“深夜纸墨”作为收束风格。

## 10. Living Library 对话（12:50–13:50）

**画面：** 进入 `/living-library`，选择 AI 演示馆藏。

**旁白：**

“Living Library 不是静态人物卡。用户可以选择自己擅长和希望交流的主题，向匿名馆藏发起申请。AI 演示馆藏会同意申请，用来展示答疑流程；真实用户必须经过双方同意后才能进入私密对话。”

**操作：** 创建 AI 演示会话，发送一个与当前研究主题有关的问题；展示回答和可共享的馆藏/知识资产入口。

**旁白：**

“对话可以使用当前授权的研究上下文回答，也可以共享明确选择的馆藏记录。身份、Provider 凭据和未授权私有文件不会暴露给对话另一方。”

## 11. Web 与桌面交付（13:50–14:30）

**画面：** 展示仓库 README 的运行说明、`dist` 目录和安装包文件名；可播放已录制的桌面启动画面。

**旁白：**

“项目提供可部署的 Next standalone Web 包，也提供 Windows Electron 安装包。桌面包携带构建后的服务，目标机器不需要源码和开发服务器；首次启动在本机运行服务，配置方式与 Web 部署一致。”

**画面：** 显示命令：`npm run package:web` 和 `npm run package:desktop`，不要展示密钥内容。

## 12. 收束与成果确认（14:30–15:00）

**旁白：**

“从一个模糊目标开始，Wormhole Library Agent 完成了目标拆解、真实来源检索、Open Library 分类下钻、全量总结、个人星图、混合记忆、资料上传、证据约束写作和人工复核导出。它的重点不是把页面做成演示卡片，而是让每一步都有来源、有状态、有权限边界，并能够在下一次研究中继续使用。”

**结尾画面：** 首页、研究星图、写作预览三屏拼接；显示项目名称和仓库公开地址占位符。

## 录制前检查清单

- 使用干净的演示数据库或演示账号，清除无关研究记录。
- 预先确认网络可访问 Open Library；若上游限流，准备展示明确的来源降级状态，不伪造实时结果。
- 预先准备 1 个无敏感信息的 Markdown/TXT 演示文件和 3 条可核验来源。
- Provider 演示使用遮罩值；视频中不出现密钥、Cookie、SSO 信息或真实用户数据。
- 确认浏览器端口、Web 包和桌面安装包均来自当前仓库构建结果。
- 全程使用“AI 全量搜索”“全量总结”“写作工作台”等最终产品文案，不把内部实现名称当成产品名称。
