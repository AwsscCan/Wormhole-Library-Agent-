# 性能基准实验：责任包 03 核心链路（零 LLM）

日期：2026-08-23
环境：Windows 11，Node 22，vitest 4
测试文件：`tests/performance/wormhole-performance.test.ts`
运行方式：`npx vitest run tests/performance/wormhole-performance.test.ts`

## 目的

验证"记忆/虫洞核心链路零 token、毫秒级"这一七牛云赛道核心卖点，
并以阈值断言的形式防止后续改动引入性能回归。

## 测量结果

| 环节 | 规模 | 实测耗时 | 阈值 | 结果 |
|---|---|---|---|---|
| 概念提取 extract | 1 篇 | 0.09 ms | < 2 ms | ✅ |
| 概念提取 extract | 1000 篇 | 0.7 ms | < 500 ms | ✅ |
| 文本概念匹配 extractFromText | 1000 次 | 50.3 ms | < 300 ms | ✅ |
| 概念图 BFS 路径搜索 findPath | 1000 次 | 48.4 ms | < 100 ms | ✅ |
| 虫洞生成 generate | 50 篇论文库 | 0.2 ms | < 50 ms | ✅ |
| 虫洞生成 generate | 200 篇论文库 | 0.3 ms | < 100 ms | ✅ |
| 虫洞生成 generate | 500 篇论文库 | 0.9 ms | < 250 ms | ✅ |
| 反馈→记忆 compile + apply | 1000 次闭环 | 8.8 ms | < 500 ms | ✅ |
| 记忆排序 rankWithMemory | 1000 篇重排 | 5.7 ms | < 50 ms | ✅ |

## 结论

1. **全链路毫秒级**：单次虫洞生成（500 篇库）< 1 ms；反馈→记忆→重排整条闭环 < 15 ms。
2. **零 token**：概念提取、图搜索、评分、淘汰、反馈编译、记忆应用、排序全部为确定性计算，不调用任何 LLM。LLM 只出现在队长（责任包 01）负责的摘要/综述环节。
3. **规模可扩展**：虫洞生成耗时随论文库规模近似线性增长（50→500 篇，0.2→0.9 ms），按此斜率估算 1 万篇论文库也在 20 ms 以内，满足个人文献库场景。
4. **可复现**：合成数据用确定性伪随机（mulberry32, seed=42），每次运行结果一致；阈值断言已并入测试套件，`npm test` 即可回归。

## 与其他方案对比（答辩口径）

| 方案 | 反馈生效耗时 | token 成本 | 本方案 |
|---|---|---|---|
| LLM 重排（每次反馈调模型） | 数秒 | 每次数千 token | 8.8 ms / 1000 次反馈，0 token |
| 向量库召回重排 | 数百 ms | 0 | 本方案无需向量库、无需嵌入，纯集合运算 |
