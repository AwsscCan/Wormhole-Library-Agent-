# PaperWorm — 一个会记住你的论文 Agent

> Google Scholar 帮你搜论文，搜完就不管你了。我们做一个会记住你口味、会持续改进的。

---

## 这是个什么东西

一个论文 Agent。主赛道是**七牛云——"具备反馈记忆能力的轻量 Agent 系统"**。

你输入你想研究什么，Agent 调用工具帮你完成任务。你给反馈，它记住你的偏好，下次自动参考。具体来说：

**Agent 会调用的工具（预置能力）：**

1. **搜论文** — 关键词搜，返回列表 + 一句话摘要 + 概念标签，按引用数排序
2. **读论文** — 论文太长？帮你提取论点、结论、引言核心，三十秒看完
3. **生成引用** — 粘贴一个 DOI，APA / MLA / 国标格式自动生成，一键复制
4. **文献综述草稿** — 给 3-5 篇论文，生成一段综述段落

**反馈记忆是怎么工作的：**

- 你说"这篇太理论了，我要实证的" → Agent 记住"偏好实证研究"
- 你说"这篇正好" → Agent 记住这个领域/方法论偏好
- 下次你搜论文 → Agent 自动参考记忆，优先推符合你偏好的
- 你说"用 APA 格式" → 下次自动默认 APA，不用再选

**差异化加分项——知识虫洞：**

Agent 偶尔会从你读的论文出发，顺着引用关系拐 2-3 跳，推给你一篇完全不相关领域、但思路能帮到你的论文。比如你读 AI Agent 方向的论文，虫洞拐到"机制设计"——表面不相干，实际上帮你打开了思路。这是开放原子赛道"制造意外"的体现，也是产品哲学：AI 不只是越来越像你，而是越来越知道该把你推向哪里。

## 赛道定位

### 主赛道：七牛云 — 具备反馈记忆能力的轻量 Agent 系统

**赛题要求**：用户输入任务 → Agent 规划+调用预置工具+生成结果 → 用户反馈 → 系统沉淀偏好/规则/经验 → 后续相似任务自动参考记忆。

**考查点**：记忆成本（token 费用、时间）、对话速度、记忆效果及是否准确使用。

**我们的答案**：

| 考查点 | 我们怎么解 |
|---|---|
| Agent 基础流程 | 用户输入 → orchestrator 规划 → 调用 paper_search / paper_summarize / citation_format 等工具 → 返回结构化结果 |
| 记忆偏好记录 | 用户反馈 → compileFeedback 编译成偏好 patch → 存入 L1 常驻记忆 + L4 用户画像 |
| 后续任务参考 | 新请求进来 → build_l2_injection 检索相关历史 → build_injection 注入可复用偏好/技能 → Agent 在结果中体现 |
| **记忆成本** | 论文搜索和引用格式走 API，**零 token 成本**；摘要用 OpenAlex 原文摘要兜底，Ollama 只在需要提取论点时调用 |
| **对话速度** | 核心链路（搜索+引用+记忆检索）全是 API + SQLite 查询，**毫秒级响应**；只有摘要提取走 LLM |
| **记忆效果** | /memory 页可视化展示偏好画像 + 更新历史；demo 里反馈后重新搜索，排序明显变化 |

**真实场景**：学术论文研究——每个研究生都在反复搜论文、筛选、读摘要、整理引用。这是真实的重复性任务，有真实的个性化需求（偏实证/偏理论、偏方法/偏应用、引用格式偏好）。

### 加分赛道：开放原子 — 制造一点意外

知识虫洞功能直接命中"不要继续猜用户下一步想要什么，试着创造他们自己都没想到会遇见的东西"。作为 Agent 的推荐策略之一展示，不是独立产品。

### 加分赛道：奇绩创坛 — 给现实打补丁

"论文又臭又长 + 引用格式折磨人"是任何写过论文的人都能共情的真痛点。引用格式生成 + 论文摘要 = 给学术科研流程打的补丁。

## 数据从哪来 — 全免费，不用 API Key

论文方向最大的优势：核心功能几乎不需要 LLM，数据全免费。

### OpenAlex（主力数据源）

论文界的 Wikipedia，完全免费，请求头里加个邮箱就行。

- **搜论文** — 关键词搜，返回标题、DOI、年份、作者、被引数
- **论文摘要** — 每篇论文的摘要原文（倒排索引格式，还原一下就是完整摘要）
- **概念标签** — 每篇论文自动标了 10+ 个概念，带相关度分数。比如 Transformer 论文标了：机器翻译(0.84) / Transformer(0.77) / BLEU(0.72)
- **引用关系** — 往前查"它引用了谁"，往后查"谁引用了它"
- **开放获取状态** — 标了是不是免费能看全文

实测：搜 "Attention Is All You Need"，拿到 28 篇引用文献 + 6688 篇被引文献 + 10 个概念标签 + 完整摘要。一个 API 搞定搜索、图谱、摘要、概念。

### CrossRef（引用格式专用）

DOI 号的官方注册机构。给它一个 DOI，它返回这篇论文的完整书目信息——作者名（姓+名分开）、标题、出版年份、期刊名、卷号、期号、页码、论文类型。纯字符串模板拼成 APA / MLA / 国标格式，不需要 AI。

实测：DOI `10.1109/CVPR.2017.114` 查回来完整元数据，手动拼出 APA 和国标格式。

### Semantic Scholar（备用，可不用）

也有论文搜索和引用图谱，但不带 API Key 时频繁限流（429）。OpenAlex 覆盖了它的大部分功能。只在需要它的 AI 一句话摘要（TLDR）时才调。**可以完全不用。**

## 记忆引擎 — 七牛云赛道的核心

### 已建好（local-agent 项目里的 Python 实现）

| 组件 | 文件 | 干什么 |
|---|---|---|
| **技能提炼** | `skill_extractor.py` | 多步任务完成 → 自动提炼成可复用技能。用户同义说法下次命中 → 自动注入 → uses 计数 +1 |
| **分层记忆** | `memory_layers.py` | L1 常驻记忆（memory.md，200 行去重）/ L2 会话归档（SQLite，token 检索 + 命中数排序）/ L4 用户画像（user_profile.md） |
| **Agent 大脑** | `agent_brain.py` | get_system_prompt() 注入 7 个上下文：GUI 状态 + 记忆 + 任务状态 + 摘要 + 技能 + 画像 + 历史 |

已通过端到端闭环测试：多步任务完成 → 技能提炼 → 同义说法命中 → uses 递增 → 无关请求不误命中 → L2 历史检索命中。

### 怎么搬到 Web 版

两条路（等拍板）：

- **路 A（推荐）**：用 TypeScript 重写记忆引擎。好处是 clean clone 体验好，队友 npm install 就能跑。坏处是多 2-3 天工作量。
- **路 B**：把 Python 记忆引擎包一层 FastAPI 微服务。好处是零重写，直接用已有的测通代码。坏处是队友 clone 下来还要装 Python + 依赖。

### 记忆成本分析（七牛云考查点）

| 操作 | 用不用 LLM | token 成本 | 耗时 |
|---|---|---|---|
| 论文搜索 | 不用 | 0 | ~200ms（API） |
| 引用格式 | 不用 | 0 | ~100ms（API + 模板） |
| 记忆检索（L2） | 不用 | 0 | ~5ms（SQLite LIKE） |
| 技能注入 | 不用 | 0 | ~1ms（文件读取） |
| 论文摘要提取 | 用 Ollama | 低（分块送入） | ~3-5s |
| 文献综述 | 用 Ollama | 中（多篇综合） | ~5-10s |

核心链路（搜索 + 引用 + 记忆）全是不用 LLM 的——这是我们对比其他参赛队伍最大的优势：**记忆系统本身不烧 token。**

## 知识虫洞 — 怎么做的（已验证可行）

不需要 NLP，不需要语义相似度计算。靠 OpenAlex 给每篇论文标的概念标签做集合运算：

1. OpenAlex 给每篇论文标了 10+ 个概念，每个带分数
2. 用户读论文 A（概念：Transformer / 机器翻译 / BLEU）
3. A 引用了 B，查 B 的概念（语料库语言学 / 语言学 / 哲学）
4. A 和 B 的概念重叠很少 → 差异度 ≈ 60% → B 就是虫洞目的地
5. 滑块控制差异度阈值：滑块低只推高重叠的，滑块高推跨领域的

实测案例：用户读 "Attention Is All You Need"（机器翻译领域），虫洞拐到 "Penn Treebank"（1993 年语料库语言学论文，Transformer 引用了它但领域完全不同）。更厉害的：引用 Transformer 的第一篇论文是 AlphaFold（蛋白质结构预测）——从 AI 拐到生物，这就是"制造意外"。

## 降级策略（缺什么都能跑，而且不骗人）

| 如果这个没做完 | 系统怎么办 | 给用户看到什么 |
|---|---|---|
| OpenAlex 限流了 | 走本地缓存数据 | 标"离线缓存"徽标 |
| CrossRef 挂了 | 让用户手动填元数据 | 标"手动模式" |
| Ollama（本地 AI）挂了 | 摘要用 OpenAlex 自带的原文摘要 | 标"原文摘要，未提取论点" |
| 虫洞算法没写完 | 走引用图谱确定性路径（2-3 跳），滑块照样影响排序 | 用户无感知 |
| 引用地图没画 | 只展示论文列表 | 隐藏地图入口 |
| 推送没做 | 降级为站内通知 | "站内推送" |

**关键**：论文搜索、引用格式、记忆引擎这三个核心功能几乎不存在"做不出真"的风险——OpenAlex 和 CrossRef 是免费 API，记忆引擎已建好测通。

## 硬规矩（不许造假）

1. **反馈必须真的改变后续推荐**。用户说"太理论了"，下次推荐必须真的变。
2. **记忆必须有据可查**。/memory 页展示偏好画像 + 更新历史，不是黑箱。
3. **引用格式必须是真的**。APA 就是 APA，标点空格不能错。调 CrossRef 拿真实元数据，不编造。
4. **论文摘要必须是论文内容的真实提取**。Ollama 挂了就用 OpenAlex 原文摘要，不能用通用废话编。
5. **虫洞必须落在真实论文上**。终点必须是一篇有 DOI 的真实论文，不能凭空编。
6. **每个虫洞必须展示路径**。展示 A→B→C 的引用链，让用户理解"为什么拐到这里"。
7. **clone 下来必须能跑**。npm install && npm run dev 就能起步，不依赖外部数据库或 API Key。
